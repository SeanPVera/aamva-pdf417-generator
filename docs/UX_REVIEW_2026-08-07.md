# UX Review (2026-08-07)

> **Status: all 30 items implemented.** This document is kept as the rationale
> record — each entry states the problem that was found and the fix that shipped.
> Line references point at the code *as it was when the problem was found*, so
> they describe the defect, not the current file.

## Scope

A read-through of the shipped UI surface — `src/App.tsx`, every component in `src/components/`,
the Zustand store, and the core modules the UI depends on (`validation.ts`, `exportNaming.ts`,
`schema.ts`, `presets.ts`, `fieldHelp.ts`). Every finding below cites the line it came from.

Nothing here is a code change; this is a prioritized backlog. Items are ordered by impact, not by
implementation cost.

Context worth stating up front: the app is already well past the obvious UX work. It has grouped
fields with per-group completion counts, a required-fields progress bar in two places, inline field
help popovers, a welcome tour, a shortcuts cheat sheet, toasts, drag-and-drop import, a diff-flash
on bulk load, jurisdiction theming, lazy-loaded heavy bundles, and a whimsy layer with its own
preference toggle. The findings below are the next layer down.

## 20 substantive UX improvements

### Trust and data loss

**1. Exported filenames embed the cardholder's name.**
`buildExportBasename` (`src/core/exportNaming.ts:35-51`) produces `barcode_CA_DOE_JANE_DL.png`, and
it is used for PNG, SVG, and JSON exports (`BarcodePreview.tsx:213,248`, `Header.tsx:135-136`). The
app's entire privacy posture is that PII never touches disk — the store comment says so explicitly
(`useFormStore.ts:5-10`) and `partialize` enforces it (`useFormStore.ts:176-188`). But every export
writes the name into a filename that lands in `~/Downloads`, gets indexed by the OS search index,
syncs to cloud drive clients, and shows up in the file picker during a screen share.
**Fix:** default to `barcode_CA_DL_v10_<first 8 of DD>` and put the name-in-filename behavior behind
an explicit, persisted "Include name in filename" toggle next to the export buttons.

**2. There is no unsaved-work guard.**
`fields` is deliberately excluded from persistence (`useFormStore.ts:176-188`) and there is no
`beforeunload` handler anywhere in `src/`. A refresh, an accidental Cmd-W, or a crash silently
discards a 30-field hand-typed form. The privacy decision is right; the silence is not.
**Fix:** register a `beforeunload` guard whenever fields are dirty — `App.tsx:143-146` already
computes `anyFields` — and add one line of standing copy near the form header: *"Field values are
never written to disk. Export JSON to keep a copy."*

**3. `Clear PII` is a native `window.confirm()` with no undo path.**
`Header.tsx:164-180`. It blocks the renderer, can't be themed, is easy to muscle-memory through, and
in Electron it renders as an OS-level modal. Meanwhile `clearFields()` already pushes the previous
map onto `_history` (`useFormStore.ts:125-130`), so undo is free and unused.
**Fix:** drop the confirm, clear immediately, and show a persistent toast with an **Undo** action —
`ToastOptions.persistent` already exists (`Toast.tsx:6-9`). The same treatment belongs on preset
application (`Header.tsx:182-188`) and scan import (`WebcamScanner.tsx:67-81`), both of which
overwrite the whole form today with no announced way back.

### Correctness of what the user is shown

**4. Export JSON writes fields the current schema does not contain.**
`Header.tsx:129-140` serializes `{ state, version, ...fields }` — the entire store map. Because
`setStateVersion` leaves `fields` untouched (`useFormStore.ts:100`), values orphaned by an earlier
state or version switch stay in the store, invisible and unvalidated, and then reappear in the
export file. The user sees 28 fields on screen and gets 35 in the file.
**Fix:** filter the export through `getFieldsForStateAndVersion(state, version)` and report what was
dropped ("3 values from another version were not exported"). Silently shipping invisible data is the
part to remove, not the filtering.

**5. The preview shows a stale barcode as though it were current.**
`BarcodePreview.tsx:151` debounces generation by 300 ms. During that window the canvas still shows
the *previous* payload, the Raw Payload textarea still holds the previous string, and the export
buttons are still enabled — so a fast typist can export or copy a payload one keystroke behind what
they are looking at.
**Fix:** during the debounce, set `aria-busy` on the canvas, drop it to ~40% opacity, and disable
PNG/SVG/Print/Copy. A 300 ms "this is not settled yet" state costs nothing and closes the gap.

**6. Nothing surfaces the fields a jurisdiction excludes.**
`AAMVA_STATE_EXCLUDED_FIELDS` (`schema.ts:219-231`) prunes the form silently. Switching CA → NY makes
`DAW`, `DAX`, `DAZ`, and `DCL` disappear with no explanation, which reads as a bug rather than as
correct behavior.
**Fix:** a dismissible line under the state selector — *"NY excludes 4 fields at v09: DAW, DAX, DAZ,
DCL"* — with a popover explaining that the jurisdiction does not encode them.

**7. Undo cannot reach past the current word.**
`setField` pushes a history entry on every keystroke (`useFormStore.ts:90-98`) against a 20-entry cap
(`useFormStore.ts:14`). Typing `SAN FRANCISCO` into DAI consumes 13 of 20 slots, so Ctrl+Z can never
get back to the previous field — and the header badge advertising "9+" available steps
(`Header.tsx:227-234`) actively misleads about what those steps will do.
**Fix:** coalesce consecutive edits to the same field within ~600 ms into a single history entry,
breaking the coalescing on field change, undo/redo, and bulk load.

### Navigating a 30-field form

**8. There is no "issues only" view.**
`FieldFilters.tsx:98-121` offers search and "Required only"; the validation report offers "scroll to
first error" (`BarcodePreview.tsx:600-621`). With eight errors spread across six collapsed groups,
the only workflow is jump → fix → scroll back → jump again.
**Fix:** an "Issues only (N)" filter chip beside "Required only" — `App.tsx:136-142` already computes
the error set — plus `F8` / `Shift+F8` to walk to the next and previous issue.

**9. The jurisdiction picker is a flat 54-item native select sorted by abbreviation.**
`Sidebar.tsx:77-88` sorts `Object.keys(AAMVA_STATES)`, so the list reads AK, AL, AR, AS, AZ, CA… —
ordered by a code, while users think in names. Native type-ahead matches the option text, which
starts with that same code, so typing "Fl" for Florida does nothing.
**Fix:** a combobox with type-to-filter across both name and code, a persisted "Recent" group at the
top (jurisdiction codes are not PII), and territories in their own `optgroup`.

**10. Field search misses everything except code and label.**
`App.tsx:99-110` matches `f.code` and `f.label` only. Searching "donor", "REAL ID", "restriction", or
"truncation" returns nothing — even though `FIELD_HELP` (`core/fieldHelp.ts:6-38`) contains exactly
those words for exactly those fields.
**Fix:** extend the predicate to help text and group label, and indicate which part matched so a
help-text hit doesn't look like a false positive.

**11. Batch processing is wedged into the bottom of the field form.**
`App.tsx:567-571` renders `BatchProcessor` inside the scrolling fields column, below every group,
always mounted. It is a different task with a different mental model — many rows, no live preview,
its own strict-mode checkbox that duplicates the sidebar's (`BatchProcessor.tsx:317-329`) — and it
pushes the form's natural end off-screen.
**Fix:** promote it to a header entry beside Compare, rendered as a full-screen modal in the
`CompareView` mold.

**12. Batch input is JSON-array-only.**
`BatchProcessor.tsx:139-241` requires a JSON array of objects. The people who have 200 rows have them
in a spreadsheet, and the "Download template.json" affordance (`:117-127`) doesn't help with that.
**Fix:** accept CSV/TSV with a header row of AAMVA field codes, show a five-row parsed preview with
column mapping before processing, and leave the JSON path untouched.

**13. A failed batch row produces a message and nothing else.**
Errors render as a plain `<ul>` (`BatchProcessor.tsx:376-382`) — not copyable cleanly, not sortable,
not something you can hand back to whoever produced the input file. Meanwhile the successful rows
have already been committed to a PDF the user never previewed (`:230-232`).
**Fix:** add "Download error report (CSV)" and "Download successes as PNGs (ZIP)" beside the results
block, and gate `pdf.save()` behind a preview step showing page count and per-row status.

### Accessibility and input

**14. No modal traps focus, and the scanner manages none at all.**
`ShortcutsModal.tsx:55-71`, `CompareView.tsx:35-50`, and `WelcomeTour.tsx:84-106` each set initial
focus and handle Escape, but Tab still walks into the page behind them. `WebcamScanner.tsx:196-210`
has no Escape handler, no focus restoration, and no trap — while a live camera stream is running.
**Fix:** one shared `useModalShell({ onClose })` hook doing trap + restore + Escape, applied to all
four. This also removes four copies of the same effect.

**15. The character counter is an `aria-live` region that fires on every keystroke.**
`FieldInput.tsx:271-278`. A screen-reader user typing a street address hears "1 of 35", "2 of 35",
"3 of 35" — the counter interrupts the field's own feedback continuously.
**Fix:** drop `aria-live` from the counter, keep it visual, and announce only at thresholds (80% and
at the cap) through a separate polite region.

**16. Validation messages are truncated with no way to read them.**
`FieldInput.tsx:241-269` renders the advisory absolutely positioned, single-line, and `truncate`d,
with no `title` fallback. `evaluateFieldValue` emits messages like *"Value must be one of: BLK, BLU,
BRO, GRY, GRN, HAZ, MAR, PNK, DIC, UNK."* (`validation.ts:529-533`) — clipped to roughly the first
six characters in a three-column grid.
**Fix:** allow two lines and add `title`; better, render enumerated-value errors as a popover of
clickable chips that set the field on click.

**17. Every shortcut is labelled "Ctrl" on macOS.**
The handler correctly accepts `e.metaKey` (`App.tsx:389`), but `ShortcutsModal.tsx:19-39` hardcodes
`["Ctrl", "Z"]` and the header tooltips say "Ctrl+Z" / "Ctrl+Shift+Z" (`Header.tsx:222,239`). Mac
users are told the wrong key for every shortcut the app has.
**Fix:** a `modKey()` helper returning ⌘ or Ctrl, consumed by both the cheat sheet and the tooltips.

**18. Two shortcuts work by scraping the DOM, and one breaks outright.**
`handleCopyPayload` locates the payload with
`document.querySelector("textarea[aria-label='Raw AAMVA payload string']")` (`App.tsx:259-274`) and
`handleExportPNGShortcut` clicks a button found by `aria-label` (`App.tsx:276-281`). Both depend on
label strings that accessibility work will legitimately reword. Worse, Raw Payload is a
`CollapsibleSection` that unmounts its body when closed (`BarcodePreview.tsx:91-95`) — so collapsing
that section silently breaks Ctrl+Shift+C, and the user gets "No payload to copy yet." while looking
at a rendered barcode.
**Fix:** lift the generated payload into the store (or a small context) so the panel and the
shortcuts read one source of truth.

### Defaults and polish

**19. Theme defaults to dark and ignores the OS.**
`useFormStore.ts:78` hardcodes `theme: "dark"` for first-time visitors, and nothing in `src/` reads
`prefers-color-scheme`. A user on a light-mode desktop gets a dark app on first paint with no
explanation.
**Fix:** add a `system` theme value that follows the media query and make it the default, keeping
light / dark / dmv as explicit overrides. The theme toggle already renders three states cleanly and
has room for a fourth (`Header.tsx:257-283`).

**20. The inspector is a fixed 320 px column that cannot be widened.**
`BarcodePreview.tsx:378` pins the panel at `lg:w-80`. It holds the raw payload textarea, the decoded
field table, and the validation list; decoded values wrap with `break-all` (`:693`). Meanwhile the
form column spreads fields across four columns at `2xl` (`FieldGroup.tsx:75`). The panel a QA user
reads most is the most cramped element on the page.
**Fix:** make the divider draggable with a persisted width, and add an "expand inspector" control
that promotes payload + decode + validation into a full-width modal.

## 10 funny, whimsical, or gloriously superfluous additions

The app already has Gus the clerk mascot with mood-matched quips, state-animal confetti, a
tilt-reactive holographic shimmer, an APPROVED stamp, a Konami disco mode, and synthesized
stamp clicks. These build on that layer rather than repeat it, and all of them belong behind the
existing `whimsy` / `soundOn` preferences (`useFormStore.ts:119-121`) and the
`prefers-reduced-motion` guard already in `styles/index.css:578-582`.

**1. Take a number.**
A deli-counter ticket dispenser. On load you get a stub in the corner — *A-047* — and a flip-board
reads **NOW SERVING 046**. It advances when your barcode generates. During batch processing it
advances per row, which turns the progress bar into something worth watching.

**2. Hold music.**
While `BatchProcessor` runs, a synthesized 8-bit hold loop — same no-assets Web Audio approach as
`useClickClack` — under a rotating caption: *"Your barcode is important to us. Please remain in the
queue."* It cuts off mid-phrase the instant processing finishes, exactly like real hold music.

**3. Gus takes his break.**
Extend the `asleep` mood (`ClerkMascot.tsx:33-45`): after five idle minutes he props a hand-lettered
**BACK IN 15 MINUTES** sign against the window, the form dims behind a WINDOW CLOSED ribbon, and the
next keystroke gets *"…fine. You're my last one today."*

**4. The laminator.**
On Export PNG, the preview slides right-to-left between two hot rollers with a moving specular
highlight and a satisfying *ka-chunk*, then drops out the far side with a two-second CSS heat
shimmer. A DOM overlay only — it must never touch the canvas or a single byte of the export.

**5. Height silhouette.**
As `DAU` is typed, a one-bit stick figure grows and shrinks against a booking-photo height chart
beside the field. Under 4'0" it slouches. Past 7'0" it holds a basketball and the help text quietly
updates to *"Verify with a second clerk."*

**6. Employee of the Month.**
A framed plaque in the sidebar awarding badges the app can already detect: *All 54 jurisdictions
visited*, *Zero validation errors on first generate*, *Clean sweep — 20 undos, no redos*, *Night
shift — a barcode after 2 a.m.* Stored as counters only, no PII. Gus's photo occupies the frame
until you earn one, and he is visibly pleased about that.

**7. DMV Bingo.**
A hidden card opened from the Playful extras menu, with squares for *took a number*, *strict mode
rejected you five times*, *generated the same DD twice*, *typed a name in lowercase*, *changed state
after filling the form*. Free space reads YOUR PAPERWORK IS INCOMPLETE. A blackout earns one quiet
BINGO stamp and nothing else, which is the joke.

**8. License plate frame.**
In DMV theme, the preview gets a jurisdiction-correct plate frame: state name in something close to
the right typeface, the actual slogan (*Live Free or Die*, *Famous Potatoes*, *The Ocean State*), and
a bolt at each corner. `STATE_THEMES` already carries a per-jurisdiction `motif`
(`Header.tsx:194,210`) to hang the variants off.

**9. The stamp cursor.**
Hovering the preview swaps the cursor for a wooden rubber stamp. Clicking thunks a rotated red
**SPECIMEN** impression onto a DOM overlay at a random ±6°, with a touch of ink bleed. They
accumulate until cleared, and they are structurally incapable of reaching the exported PNG — which
is both the safety property and the point.

**10. Read it back to me.**
A button that hands the decoded payload to `speechSynthesis` in a flat clerk monotone: *"Doe. Jane.
Q. Expires oh-one, oh-one, twenty twenty-nine. Next."* Rate 0.85, pitch 0.7, a full beat of silence
at every field boundary. Entirely local, gated behind the sound toggle, and genuinely useful for
proofreading a form you have been staring at for twenty minutes.

## What shipped

All twenty substantive items and all ten whimsy items are implemented. Notes on the ones whose
implementation differs from, or goes beyond, the description above:

- **#1** — the default basename is now `barcode_CA_DL_V10_<8 chars of DD>`; the name is added only
  when the user ticks the opt-in beside the export buttons. The e2e export assertions were rewritten
  to assert the *absence* of name tokens by default.
- **#5 / #18** — solved together by hoisting generation into `src/hooks/usePayload.ts`. Staleness is
  derived by comparing an input signature against the signature the current result was built from,
  so there is no `stale` state to fall out of sync. The preview now takes the payload as a prop and
  hands its PNG exporter back up, which removes both DOM-scraping shortcuts.
- **#13** — the PNG archive is produced by `src/core/zip.ts`, a ~100-line store-only ZIP writer
  written in-repo rather than adding a dependency to a project with a bundle budget. PNG data is
  already DEFLATE-compressed internally, so storing costs almost nothing.
- **#14** — one `useModalShell` hook now provides trap, restore, and Escape for all six modals
  (the four named plus the two new ones), replacing four hand-rolled copies.
- **#20** — the divider is draggable, double-click-resets, and keyboard-operable (arrows resize,
  Home resets); the width persists.

Two findings surfaced during implementation that were not in the original list and were fixed:

- The jurisdiction options rendered their code and name with no text node between them, so the
  accessible name came out as `"CACalifornia"`. An explicit separator was added.
- The queue ticket initially marked its whole subtree `aria-hidden` while containing a focusable
  dismiss button — an axe `aria-hidden-focus` violation. The decorative panels and the control are
  now marked separately.

**Bundle impact.** The new first-paint code pushed Initial JS from 34 kB to 44 kB. Lazy-loading the
on-demand modals (shortcuts, compare, batch, plaque, bingo, tour) and the ticket dispenser, plus
keeping the badge catalog out of the store's import graph, brought it back to 38.4 kB. The budget
in `.size-limit.json` was raised 38 → 40 kB to cover the remaining ~0.4 kB of genuinely
first-paint work (the jurisdiction combobox, the modal shell, the issues filter).
