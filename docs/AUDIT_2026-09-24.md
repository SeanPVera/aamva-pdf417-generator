# Engineering and product audit — 24 September 2026

Repository: `SeanPVera/aamva-pdf417-generator` (the repository matching the supplied `SeanPVera/AAMVA-pdf417` name; that exact path did not resolve).

Reviewed baseline: clean `main`, **`90f3216faf0d3b0c50f49551676bb04f4e60d874`**. Implementation branch: **`codex/adversarial-audit-workspace-redesign`**. This report accompanies the branch diff; no merge, release, or deployment is part of this work.

## A. Executive summary

This was an established application with substantial useful engineering, not an empty prototype: 980 tests in 59 files passed at baseline, as did lint, formatting, type checking, and the production build. It already had property tests, provenance-tagged fixtures, an independent ZXing barcode oracle, lazy bundles, a hardened Electron boundary, and deliberate PII exclusions from persistence.

Nevertheless, green tests concealed important data-integrity defects. The encoder could delete unsupported name characters; the address jurisdiction was overwritten with the issuer; import could lose the ID document type and extensions; undo could restore fields without their document configuration; and several malformed records were accepted or partially discarded. Rendering and export failures could still appear successful. The repair controls themselves could truncate or transliterate identity data. These are reproducible behavior defects, not speculative threats.

The branch repairs those boundaries, adds targeted regressions, limits hostile inputs, makes file import transactional, and makes erasure remove undo history. Generation now fails explicitly for unsupported characters; it does not pretend that ASCII-only generation implements the standard's entire repertoire. Default filenames no longer reveal document identifiers. Vitest was patched for a development-only advisory; the dependency audit now reports zero vulnerabilities.

The interface is rebuilt around a **record workbench**: horizontal record settings and numbered sections; a flexible editor beside a white PDF417 proof; explicit import; four diagnostic views; and a restrained paper/ink/oxide design system. The old jurisdiction-colored shell, imitation credential decoration, games, and automatic tour no longer occupy the working interface. Useful editing, scanning, comparison, batch, export, keyboard, PWA, and desktop capabilities remain.

## B. Bug inventory

Severity reflects realistic impact in a local record-processing utility. No critical remote compromise or committed secret was established. “High confidence” below means the behavior and repair are supported by code tracing and an executable regression; it does not imply issuer certification. Tests named below live under `src/tests/` unless prefixed `e2e/`.

### Critical

None confirmed.

### High

**H1 — Identity characters silently changed or deleted.**

- **Location / trigger:** `core/generator.ts`, `FieldInput.tsx`; encode a name containing accents, non-ASCII characters, or control bytes; type a character whose uppercase form expands.
- **Root cause / impact:** normalization and character stripping changed the record before validation, producing plausible but different identity data.
- **Fix:** reject unsupported generator input explicitly, preserve the entered value, and avoid Unicode-expanding live casing. Printable ASCII remains a documented implementation limit.
- **Regression / confidence:** `adversarialAudit.test.ts`, `aamva.test.ts`; three hostile character cases failed before repair. High.

**H2 — Address jurisdiction forcibly became the issuer.**

- **Location / trigger:** `generator.ts`, `usePayload.ts`, `derivedFields.ts`, form; a CA-issued record with an NV address.
- **Root cause / impact:** DAJ was treated as derived issuer metadata, made read-only, and overwritten during generation. The barcode could contain an incorrect address.
- **Fix:** independently editable, required DAJ; issuer continues to come from the header IIN.
- **Regression / confidence:** `adversarialAudit`, `derivedFields`, `aamva`, `e2e/ux-affordances`; pre-fix regression failed. High; backed by the 2020/2025 DAJ definition.

**H3 — ID imports could become DL records.**

- **Location / trigger:** `decoder.ts`, `pasteImport.ts`, scanner/store; import an ID while the editor is set to DL.
- **Root cause / impact:** document type did not travel consistently with the field map. Subsequent generation used the previous document type.
- **Fix:** carry DL/ID metadata through raw decode, JSON, paste, scan, and one atomic store load. For v10/v11 IDs, exclude the three confirmed DL-only driving-privilege elements and DL age rules.
- **Regression / confidence:** `adversarialAudit`, `pasteImport`, `WebcamScanner`, `e2e/workbench`; JSON ID regression failed before repair. High for transport and v10/v11 distinctions; older-version ID semantics remain unverified.

**H4 — Undo mixed record fields with another document's configuration.**

- **Location / trigger:** `useFormStore.ts`; import or switch issuer/version/type, then undo.
- **Root cause / impact:** history stored fields alone. Restored identity data could be encoded under the newer issuer, version, or type.
- **Fix:** document snapshots contain issuer, version, type, fields, and original source. Import and configuration changes are reversible as whole-document operations.
- **Regression / confidence:** `adversarialAudit`, `importLifecycle`, `e2e/workbench`; baseline atomic-history regression failed. High.

### Medium

**M1 — “Fix all” could destroy information.** `quickFix.ts` offered truncation, transliteration, prefix guesses, and arbitrary first-character extraction; it also uppercased opaque extensions. Overlong cities/names or “NOT SURE” could turn into different valid-looking data. Repairs now use exact aliases and unambiguous formatting; they preserve internal name spacing, reject ambiguous postal/height rewrites, and leave unsupported/opaque data alone. Five regressions failed before repair in `quickFix.test.ts`. **Confidence: high.**

**M2 — Malformed or truncated wire data could pass.** `decoder.ts` accepted a missing primary CR terminator, skipped malformed element lines, allowed unaccounted bytes before the first subfile in strict mode, and could repair substantial overlaps. It now checks directory counts, strict contiguous framing, bounded overlap tolerance, element syntax, controls, and primary terminators; parsing is resource-bounded. `adversarialAudit`, existing `decoder`, `property`, `inspect`, and conformance tests cover the repair. **Confidence: high for tested boundaries; tolerance remains an interoperability policy.**

**M3 — Conflicting duplicates silently selected the last identity.** Duplicate DCS/other codes were assigned repeatedly into a map in `decoder.ts`. Conflicting repeats now fail with a named error; identical repeats are semantically merged. `adversarialAudit` reproduces the old overwrite. **Confidence: high.** Repeating-field syntax is still not modeled as a general list.

**M4 — Imports dropped extensions or changed opaque bytes.** `pasteImport.ts` filtered by known schema codes, while decoding trimmed trailing spaces from Z subfiles; CSV also trimmed opaque cells. Unknown shaped element codes now survive record import and JSON export; Z values retain case and spaces. Fields outside the selected schema are visibly listed as excluded from regenerated output. `adversarialAudit`, `pasteImport`, and `wireLedger` cover unknown and NY-shaped data. **Confidence: high.** Arbitrary source bytes remain distinct from regeneration.

**M5 — JSON boundaries accepted unsafe shapes.** Nested/numeric field values, unsupported configuration, or bad document types could reach the store or scanner. `importPayload.ts`, `decoder.ts`, and `useFormStore.ts` now share string-only record validation and fail before mutation. This protects leading zeros and avoids objects reaching controlled text inputs. `adversarialAudit` and `importPayload` cover malformed objects, metadata, and size. **Confidence: high.**

**M6 — Batch parsing could silently reinterpret or overwhelm input.** CSV duplicate headers overwrote cells, surplus columns were discarded, malformed quoting was tolerated, and JSON rows could be null/arrays/numbers. Batch input was unbounded. `csv.ts` / new `batchInput.ts` reject ambiguous rows, bound 5 MB / 1,000 rows, and preserve valid quoted data. `adversarialAudit`, `csv`, and the browser batch-error path cover the changes. **Confidence: high.**

**M7 — Late asynchronous work could replace newer work.** File reads and image decodes could complete after edits, another selection, cancellation, or unmount. New `useRecordImport.ts`, scanner guards, per-side comparison tokens, and batch cancellation keep late results from applying. Errors preserve the document; object URLs and camera controls are cleaned up. `importLifecycle` covers newer edits, unmount, out-of-order files, and atomic undo; `WebcamScanner` covers scanner lifecycle. **Confidence: high for tested paths; real cameras remain manual.**

**M8 — Erasure retained the identity in history.** `clearFields()` left prior values recoverable by undo, and a toast could retain a restoration closure. It now clears fields, source, undo, redo, edit coalescing, and change markers; the confirmation accurately explains its scope. `adversarialAudit` and `e2e/workbench` prove undo cannot recover the erased record. **Confidence: high.** This is application-state erasure, not guaranteed forensic memory zeroization.

**M9 — Persistence trusted more than its write whitelist.** Zustand's default merge could restore injected/legacy identity data, invalid configuration, or non-function action values from localStorage. The hydration merge now accepts only validated preferences, bounds dimensions, and ignores records/history/actions. `importLifecycle` checks hostile saved preferences; existing store tests check normal PII exclusion. **Confidence: high.** Same-origin script compromise itself is outside this protection.

**M10 — Preview invented values absent from the form.** `usePayload.ts` synthesized DCF/DDB while form validation still saw blanks, causing inconsistent completion counts and hidden values in output. The preview now encodes only entered values; explicit Generate/Fill actions make synthetic values visible and undoable. `usePayload.test.ts` added two failing regressions before repair. The core's opt-in batch-generation behavior is retained and documented. **Confidence: high.**

**M11 — Validation and generation disagreed.** Whitespace-only required fields could appear filled; cross-field warnings were not consistently promoted in strict UI reporting; a generated revision date could use the jurisdiction default instead of the selected version. `validation.ts`, generator helpers, and document-aware schemas now agree for these cases. `adversarialAudit`, `usePayload`, and version/strict suites cover them. **Confidence: high for implemented cases; jurisdiction assumptions are not standards evidence.**

**M12 — Render failure could look export-ready.** `BarcodePreview.tsx` caught encoder failures without making readiness depend on a successful render of the current payload. The result now records its payload identity and error; failures clear the canvas and disable downloads. `renderFailures.test.tsx` reproduces the pre-fix false-ready state. **Confidence: high.**

**M13 — Export silently substituted lower-quality output.** PNG rendering errors could fall back to the preview bitmap; SVG failure could produce bitmap content instead of vector geometry; PDF errors were not useful feedback. Export now reports failure and does not substitute another format. Oversize/non-finite print layouts fail instead of clipping. `renderFailures` and `adversarialAudit` failed before repairs; `e2e/workbench` independently decodes the actual PNG download. **Confidence: high for software paths; physical output remains unverified.**

**M14 — Filenames exposed a document identifier by default.** `exportNaming.ts` appended eight DCF characters while claiming filenames carried no personal data. Defaults now contain only issuer/type/version; name inclusion remains explicit. `whimsy.test.ts`'s filename regression failed before repair; browser exports check filenames. **Confidence: high.** Export contents remain sensitive by design.

**M15 — Read-aloud's local-processing claim was unenforced.** Browser speech voices can be remote. `useClerkVoice.ts` now requires and explicitly selects a browser-reported local voice; it cancels on unmount. `localVoice.test.tsx` checks rejection of a remote default and explicit local selection. **Confidence: high for the browser API boundary; OS implementation behavior is not independently verified.**

**M16 — Spreadsheet reports could execute formulas.** Untrusted batch metadata/error text was written into CSV reports without guarding formula-leading cells. A separate report serializer now prefixes those strings without altering record interchange CSV. `adversarialAudit` checks `=` / `@` cases. **Confidence: high.**

**M17 — Invalid random bounds could loop indefinitely.** `secureGetRandomInt()` did not reject NaN, infinity, or fractional bounds before rejection sampling. It now rejects them deterministically. Three `adversarialAudit` cases cover this public helper. **Confidence: high.** Not a demonstrated remote attack path.

**M18 — Service-worker activation deleted unrelated caches.** On a shared origin, activation removed every cache except its own current build. `public/sw.js` now deletes only this application's prefix. `serviceWorker.test.ts` seeds another application's cache and verifies preservation. **Confidence: high.**

**M19 — Keyboard and modal behavior was incomplete.** Custom radio groups lacked arrow-key behavior; modal callback identity changes could reset focus; background content was not made inert. Long comparison and version-reference tables were not keyboard-focusable. Radios now use roving focus and arrow/Home/End keys; modal focus setup is stable and isolates/restores sibling content; scrolling tables have named focusable regions. Inspector tabs have matching tab/panel relationships. `e2e/workbench`, existing component tests, and rendered Axe checks cover these paths; the added version-reference test failed before repair. **Confidence: high for browser behavior tested; screen-reader review remains manual.**

### Low

**L1 — ZIP entry encoding was unspecified.** `zip.ts` wrote UTF-8 filenames without the UTF-8 flag in local and central directory headers. Both headers now carry the flag. `adversarialAudit` and existing ZIP tests cover output. **Confidence: high.**

**L2 — Electron package version was pinned.** `package.json` forced `extraMetadata.version` to `1.0.0`, independently of future changeset versions. The override is removed so package metadata follows the actual package version. Source/configuration review confirms the correction; native packaging was blocked by this environment's binary download path. **Confidence: high in configuration, native runtime unverified.**

**L3 — Development dependency advisory.** The baseline lockfile reported three moderate entries for Vitest and its associated packages, all from the same development advisory; no high/critical entries. Vitest and coverage were patched to 4.1.11. Final `npm audit` reports zero. **Confidence: high.** This was not represented as a production-client vulnerability.

**L4 — Documentation contradicted the application.** README/core guide claimed 01–10, 54 jurisdictions, encrypted persisted records, and an all-synthetic corpus. It also described removed UI controls and asserted physical print fidelity without evidence. Current documentation records 01–11, 55 registry entries, preference-only storage, two externally derived layouts, and measured limits. Owner-like name tokens in the existing NY fixture were replaced with plainly synthetic, same-length tokens without changing offsets or layout. **Confidence: high for repository facts; external fixture provenance remains the repository's claim.**

**L5 — UI polish defects found during this redesign.** Actual screenshots revealed mobile overflow from positioned hidden section text, compressed inspector tabs, a stale white-on-pale action style, and mismatched dark control fills. Browser QA also found low-contrast stale payload text. Scoped positioning, non-shrinking inspector items, semantic surfaces, and full-contrast text repaired them; responsive and Axe tests protect the result. These were caught during implementation, not attributed to the baseline. **Confidence: high at tested sizes.**

## C. Standards findings

### Confirmed defects repaired

The 2020 and 2025 tables define DAJ as the address jurisdiction, and mark DCA/DCB/DCD as DL-only. Those facts support H2 and the v10/v11 portion of H3. Their framing descriptions support checking the fixed header/directory and the primary segment terminator. Deleting unsupported input is never a legitimate substitute for encoding the supplied record.

### Confirmed behavior retained

Generated ASCII payloads use the compliance/header markers, six-digit IIN, two-digit version fields, entry count, and ten-character directory entries. Offsets account for directory growth and actual generated bytes. Multiple subfiles and observed CT/NY layouts remain covered by fixtures. Date/calendar, constrained-code, length, strict-validation, and version tests remain in place. The existing v11 nine-digit postal representation is retained. Independent ZXing tests verify the PDF417 layer, including all modeled jurisdictions and negative controls.

### Implementation assumptions and interoperability conventions

- Strict issuer/default-version matching is this application's profile policy. It is not proof that another card version is invalid for that issuer.
- The four-byte non-strict directory tolerance and identical-repeat merging are parser policies. They are not claimed AAMVA requirements.
- NY/CT padding, order, jurisdiction versions, and extension layout come from repository provenance. They do not establish all editions or every issuer's behavior.
- ASCII byte length is correct for accepted generated input. The broader ISO-8859-1 repertoire specified by the standard is **not fully supported by generation**; Latin-1 decode plus ASCII-only generation is an explicit asymmetry.
- Unknown elements survive inspection/JSON but are not automatically promoted into a generated schema. Repeating elements are not a general lossless list model.
- The encoder's error-correction level, automatic columns, and padding are implementation choices tested in software. Print dimensions are unverified presets, and preview scaling is not physical certification.

### Requires authoritative verification

Older-version ID requirements (01–09); the complete historical mandatory/optional tables; all issuer IIN/default-version/rule-pack provenance; historical names and truncation semantics; coded values across editions; jurisdiction-specific document-number patterns, class ages, and revision dates; arbitrary subfile ordering and opaque non-Z subfiles. These were not “corrected” from memory.

Primary references consulted:

- [AAMVA 2025 DL/ID Card Design Standard](https://www.aamva.org/getmedia/81af105d-8b1b-45e1-aa46-f1800a259ed1/AAMVADLIDCardDesignStandard2025.pdf), Annex D / element tables and framing.
- [AAMVA 2020 DL/ID Card Design Standard](https://www.aamva.org/getmedia/99ac7057-0f4d-4461-b0a2-3a5532e1b35c/AAMVA-2020-DLID-Card-Design-Standard.pdf), Annex D.
- [bwip-js documentation](https://github.com/metafloor/bwip-js/blob/master/README.md), rendering/scaling options.
- [Vitest advisory GHSA-82fw-gwwq-j7x9](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9), patched version and development-only scope.
- [SpeechSynthesisVoice.localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService), local/remote voice distinction.

## D. Architecture findings

The application is a client-only React/Zustand utility. `schema.ts` and issuer/rule data drive the forms; `usePayload` debounces encoding; `BarcodePreview` owns rendering and export; ZXing is loaded for scanning; jsPDF supplies PDF output. PWA precaching and the Electron wrapper are separate deployment concerns. There is no application backend.

Useful separation was retained. The work did not replace React, Vite, Zustand, the schema registry, the encoder, or the decoder libraries. Import validation and asynchronous file handling are now shared boundaries; history represents a whole document; readiness represents an actual render. Duplicate generated/entered state was removed from the live preview. Actual source bytes remain separately inspectable.

The baseline design spread visual rules across jurisdiction palettes, large CSS selectors, Tailwind classes, optional decoration, and component logic. Semantic tokens now control the working UI. Decorative components are unmounted and their main-workflow counters/effects removed. Legacy game/palette modules and some compatibility store fields remain source-tested but are deliberately not comprehensively deleted in this change; deleting public or historical APIs without a usage audit would add unrelated risk.

Dependencies were retained where they contribute: bwip-js encoding, ZXing decode, jsPDF export, React/Zustand UI/state, Electron packaging, and the existing test/toolchain. No new production dependency was added. The only package update addresses the verified Vitest advisory.

Main-thread encoding still exists. Debouncing and lazy loading remain, but this review does not claim a measured CPU/latency improvement. Bundle size changes are reported under validation. A worker rewrite was not justified without profiling representative large inputs.

Security inspection covered renderer privileges/navigation, CSP, SW caching, file/image limits, downloads and ZIP paths, clipboard paths, persistence, logging/error handling, and dependencies. The existing Electron isolation/navigation policy was retained. No high-confidence committed credential was found in reviewed application/configuration files; this was not an exhaustive historical secret-forensics engagement. A meta-delivered `frame-ancestors` directive is not an effective framing defense; deployment headers would be needed where that matters.

## E. Critique of the prior design

The old shell allocated attention to issuer branding, decorative credential imagery, a separate navigation column, and long vertically stacked diagnostics. Those treatments suggested an issuing authority more strongly than they explained the edit → inspect → export workflow. Large controls, headings, and reserved helper space competed with the many fields; related output and diagnostic information could be far apart. Automatic onboarding could interrupt a usable screen.

Theme colors depended on the selected issuer even though issuer selection is record data, not a navigation state. Styling was distributed between broad selectors and component utilities, which made contrast and dark-mode behavior hard to reason about. The E2E accessibility scan explicitly filtered out contrast violations. Multiple header menus and mobile-specific action arrangements made capabilities harder to locate consistently. “Clear” did not match its privacy implications, and apparently valid output did not always mean rendering had succeeded.

The new interface addresses those functional causes, rather than adding fashionable decoration.

## F. New design direction

[The design concept was written before implementation](design/WORKBENCH.md). The organizing metaphor is a technical document and its machine-readable proof. The barcode's horizontal geometry supplies the small product mark; numbered sections and typographic rules supply structure. No seal, simulated license, glass effect, gradient, ambient animation, or decorative metric cards are used.

Tokens cover paper/surfaces, ink/secondary/muted text, rules/control borders, accent, success/warning/error, selection/focus, spacing, type, controls, radii, motion, and overlay elevation. A four-pixel spacing basis and 44-pixel controls support density and hit targets. Small 3-pixel control corners and 6-pixel overlay corners have distinct roles. Atkinson Hyperlegible Next handles human reading; JetBrains Mono is reserved for codes, bytes, and numerical interpretation. Fonts remain local and offline-capable.

Light and dark modes share meaning and hierarchy; white barcode paper remains invariant. Repairs are explicit, failures preserve input, and empty required fields read as work remaining rather than a screenful of alarms. Motion is limited to short state feedback and respects reduced-motion preference.

## J. Remaining risks and limits

- **Standards:** a modeled version/issuer and a green application validator are not a conformance certificate. Full Latin-1 generation, historical ID distinctions, registry/rule provenance, and arbitrary repeated/subfile layouts remain incomplete.
- **Physical output:** ideal-contrast ZXing round trips do not prove printed scanning reliability. Validate real printers, DPI/scaling settings, paper, quiet zones, dense payloads, scanner engines, and camera optics. The batch page-fit PDF and single-record print presets still differ.
- **Platforms:** Firefox/WebKit, real iOS/Android, and native Windows/macOS/Linux packaging need their configured CI/device gates. Chromium mobile emulation is not an iPhone or Android camera.
- **Privacy:** memory-only records can still be exposed by an already-compromised same-origin environment, extensions, clipboard managers, downloads, printing, or the OS. Erasure is not forensic zeroization. Speech locality trusts the browser's voice metadata.
- **Architecture:** legacy decorative source/store compatibility remains; barcode and batch work still runs on the main thread. No unsupported performance or security-certification claim is made.
- **Fixtures:** only two of 55 modeled jurisdictions have externally derived layouts, and the provenance was not independently re-acquired from the original credentials during this audit.
